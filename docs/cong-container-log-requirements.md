# Cong Container Log 洗い替え要件

更新日: 2026-06-06

## 目的

既存の写真記録アプリを、港湾コンテナのログ記録アプリ `Cong` として洗い替える。

写真を単に保存するだけでなく、コンテナ業務で使う記録種別を写真ごとに付与し、あとからコンテナ番号、搬入、搬出、シール、損傷、その他の記録を追いやすくする。

コンテナ番号は、データ上のまとまりとして登録するだけでなく、実物のコンテナ番号を撮影した写真としても記録する。入力値と現物写真の二重記録になり、やや重複感はあるが、コンテナ番号がずれた場合の影響が大きいため、証跡性を優先してこの運用を採用する。

## 対象範囲

- アプリ本体の名称変更
- アプリ本体のロゴ、favicon 差し替え
- アプリ本体のブランドカラー変更
- 写真登録時のタグ選択追加
- フォルダ表示名をコンテナ番号へ変更
- タグ別サマリとタグ検索の追加
- 写真一覧、詳細、出力、API 保存でタグを扱えるようにするための要件整理

## 対象外

- LP はまだ変更しない
- LP 用のコピー、画像、価格訴求、SEO 文言は変更しない
- 課金、チーム、認証の基本仕様は今回の主対象にしない
- 内部 API パスや DynamoDB 上の `folder` 命名は、必要がなければ変更しない

## ブランド要件

### 名称

- アプリ名は `フォトスマ` から `Cong` に変更する
- サブタイトルは `Container Log` とする
- ブラウザタイトル、ヘッダー、ログイン後のアプリ内表記は `Cong` を基本表示にする
- 必要に応じて `Cong | Container Log` のようにアプリ名とサブタイトルを併記してよい

### ロゴ・favicon

以下の画像をアプリ本体で使用する。

- `frontend/img/cong-logo.png`
- `frontend/img/cong-favicon.png`

既存の `photosma` 系ロゴは、LP を除くアプリ本体では表示しない。

### ブランドカラー

アプリ本体のブランドカラーは以下に変更する。

```css
:root {
  --cong-navy: #06224A;
  --cong-blue: #1E90FF;
  --cong-white: #FFFFFF;
  --cong-bg: #F5F5F5;
}
```

基本方針:

- 主要なヘッダー、強調文字、重要な枠線には `--cong-navy` を使う
- 主要アクション、選択状態、アクセントには `--cong-blue` を使う
- 背景は `--cong-bg` を基準にする
- 白い面は `--cong-white` を使う
- 既存の PhotoSma 色がアプリ本体に残らないようにする

## 写真タグ要件

### タグ種別

写真には以下のタグを 1 つ付与できるようにする。

- コンテナ番号
- 搬入
- 搬出
- シール
- 損傷
- その他

`コンテナ番号` タグは、対象コンテナの識別子そのものではなく、入力したコンテナ番号が現物と合っていることを確認するための写真種別とする。

対象コンテナの識別子は、既存のフォルダ名にあたる `コンテナ番号` として別に扱う。

### 入力要件

- 写真登録時の写真名入力はなくす
- 写真登録時はタグ選択プルダウンを表示する
- タグはプルダウンから選択する
- タグは写真ごとに選択できるようにする
- 複数写真を同時登録する場合も、各写真行で個別にタグを選択できるようにする
- 初期値は `コンテナ番号` で確定する
- タグ未選択のまま保存される状態は作らない
- 写真名はユーザー入力させない
- 保存時の写真名は `コンテナ番号_タグ名_連番` で自動生成する
- 連番は同一コンテナ番号・同一タグ内で採番する
- 連番は 3 桁ゼロ埋めとする
- 例: `TCLU1234567_コンテナ番号_001`
- コンテナ番号タグは、入力したコンテナ番号が正しいか確認する写真に使う
- 通常の作業フローでは、まず `コンテナ番号` 写真を登録し、その後に `搬入` 以降の作業写真を登録する想定とする
- `コンテナ番号` 写真は、将来的に AI/OCR で写真内のコンテナ番号を読み取り、入力されたコンテナ番号と照合するための証跡にもする

### UI配置

写真アップロード対象一覧の各行は、以下の順で表示する。

1. 元ファイル名またはプレビュー
2. タグ選択プルダウン
3. 初回コメント入力欄
4. 個別除外ボタン

写真名入力欄、写真名連番反映ボタン、写真名編集導線は Cong では表示しない。

### 表示要件

写真一覧カードには、保存済みタグを表示する。

- 写真名は表示しない
- タグバッジを表示する
- タグバッジは一覧で視認しやすい位置に置く
- タグ未設定の既存写真がある場合は、表示上 `その他` として扱ってよい
- タグごとに色分けする

写真プレビューやコメント欄を開いたときも、タグを確認できるようにする。

### タグ色分け要件

タグは一覧、サマリ、検索結果、レポートで同じ色を使う。

確定色:

- `コンテナ番号`: ネイビー `#06224A`
- `搬入`: ブルー `#1E90FF`
- `シール`: パープル `#7C4DFF`
- `損傷`: レッド `#E53935`
- `搬出`: グリーン `#2E7D32`
- `その他`: グレー `#607D8B`

色の意図:

- `コンテナ番号`: 対象確認、識別
- `搬入`: 到着、受付、開始
- `シール`: 特別確認、セキュリティ
- `損傷`: 異常、注意
- `搬出`: 完了、OK
- `その他`: 補助分類

### 編集要件

保存済み写真のタグは編集できるようにする。

- 既存の写真名修正 UI は使わず、タグ変更 UI に置き換える
- タグを保存対象にする
- タグ変更時は、必要に応じて自動生成される写真名も `コンテナ番号_タグ名_連番` に更新する
- 編集権限は既存の写真名修正と同じく、作成者または管理者とする
- タグ変更時は監査ログを残す
- 監査ログには変更前タグ、変更後タグ、変更前 `fileName`、変更後 `fileName`、更新者、更新日時を含める
- タグ変更後の `fileName` が再生成されても、監査ログで元の登録状態を追えるようにする

## コンテナ番号要件

既存の `フォルダ` は、ユーザー向けには `コンテナ番号` として扱う。

### 表示名変更

- `フォルダ` という表示文言は、アプリ本体では `コンテナ番号` に変更する
- `フォルダ作成` は `コンテナ番号登録` に変更する
- `現在のフォルダ` は `現在のコンテナ番号` に変更する
- `フォルダを選択してください` は `コンテナ番号を選択してください` に変更する
- `folder-detail-title` の表示も `コンテナ番号: {container}` を基本にする
- 内部変数名、API パス、DB キーの `folder` は、実装コストを抑えるため残してよい

### コンテナ番号と写真名

- 既存のフォルダ名入力欄は、コンテナ番号入力欄として使う
- 写真名は入力させず、コンテナ番号、タグ名、連番から自動生成する
- 連番は同一コンテナ番号・同一タグ内で 3 桁ゼロ埋め採番する
- 自動生成例: `TCLU1234567_コンテナ番号_001`
- 同じコンテナ番号内でも、タグが異なる場合はタグごとに `001` から始める
- 例: `TCLU1234567_コンテナ番号_001`、`TCLU1234567_搬入_001`、`TCLU1234567_損傷_001`
- 画面上では写真名を原則表示せず、タグと写真を主情報にする

### フォルダパスワード機能

フォルダパスワード機能は現状維持とする。

- 既存の鍵付きフォルダ仕様は変更しない
- コンテナ番号表示へ変えても、鍵付きデータのアクセス制御は現状どおり維持する
- パスワード入力、設定、解除の UI は既存仕様のまま残す
- backend API も現状維持とする

## タグサマリ要件

`folder-detail-title` の下に、選択中コンテナ番号内のタグ別件数サマリを表示する。

表示対象:

- コンテナ番号
- 搬入
- 搬出
- シール
- 損傷
- その他

表示例:

```text
コンテナ番号 1 / 搬入 3 / 搬出 2 / シール 1 / 損傷 0 / その他 1
```

要件:

- 写真一覧の読み込み結果から件数を集計する
- タグ未設定の既存写真は `その他` に含める
- タグバッジと同じ色分けで表示する
- 件数が 0 のタグも表示する
- フォトフォルダ、クエストフォルダのどちらでも写真がある場合は同じサマリを表示する

## クエスト写真のタグ要件

クエストモードで写真を追加する場合も、写真には同じ `logTag` を持たせる。

- クエスト写真追加時にもタグ選択を表示する
- タグ初期値は `コンテナ番号` とする
- クエスト写真もタグ別サマリの集計対象にする
- クエスト写真の写真名も `コンテナ番号_タグ名_連番` で自動生成する
- クエスト写真でも画面上の写真名表示はしない
- クエスト写真のタグ未設定データは `その他` として扱う

## 検索・絞り込み要件

タグによる検索・絞り込みを追加する。

### スコープ

検索スコープは以下を切り替えられるようにする。

- 現在のコンテナ番号
- 現在のお部屋

UI では「どの範囲を検索しているか」が明確に分かるようにする。

表示案:

- 検索バー左側にスコープ切替のセグメントコントロールを置く
- `このコンテナ` / `このお部屋` の 2 択にする
- デフォルトは `このコンテナ` とする

### フィルター

- タグフィルターを追加する
- `すべて` `コンテナ番号` `搬入` `搬出` `シール` `損傷` `その他` から選べるようにする
- タグバッジと同じ色を使い、現在の選択状態が分かるようにする
- コンテナ番号単位では、現在選択中コンテナの写真だけを絞り込む
- お部屋単位では、現在のお部屋に属する全コンテナ番号の写真を対象にする
- お部屋単位の検索結果には、どのコンテナ番号の写真か分かる表示を入れる
- お部屋単位検索は backend API を追加して実装する
- 検索 API はログインユーザーの閲覧権限を考慮し、見られるコンテナ番号の写真だけを返す
- 写真件数が増えても一覧取得を総当たりしなくてよいように、backend 側でタグ条件とスコープ条件を処理する

### 検索API要件

お部屋単位検索用に backend API を追加する。

候補:

- `GET /rooms/{roomId}/photos/search`

クエリ条件:

- `logTag`
- `containerNumber`
- `keyword`
- `sort`
- `limit`
- `nextToken`

要件:

- `logTag` は `all` または許可されたタグ値を受け取る
- `containerNumber` は対象コンテナ番号で絞り込む場合に使う
- `keyword` はコンテナ番号、初回コメント、通常コメント、投稿者名の検索に使う
- `sort` は `newest` / `oldest` を指定できる
- `limit` は 1 回の返却件数上限を制御する
- `nextToken` でページングできる
- レスポンスには写真情報に加えて、所属コンテナ番号を含める
- レスポンスには次ページがある場合だけ `nextToken` を含める
- ログインユーザーが閲覧できないコンテナ番号の写真は返さない
- 鍵付きコンテナ番号の扱いは既存フォルダパスワード仕様に合わせる

### 検索語

MVP ではタグフィルターを主検索とする。

必要に応じて、以下をテキスト検索対象にする。

- コンテナ番号
- 初回コメント、通常コメント
- 投稿者名

## 保存要件

### データ項目

写真レコードにタグ項目を追加する。

候補名:

- `logTag`

保存値:

- `container_number`
- `inbound`
- `outbound`
- `seal`
- `damage`
- `other`

表示文言:

- `container_number` -> `コンテナ番号`
- `inbound` -> `搬入`
- `outbound` -> `搬出`
- `seal` -> `シール`
- `damage` -> `損傷`
- `other` -> `その他`

内部保存値は英字キーにし、画面表示だけ日本語にする。

### API要件

`POST /folders/{folderId}/photos` の保存処理で、写真ごとの `logTag` を受け取る。

- 許可された値以外は保存しない
- 未指定または空の場合は `container_number` にフォールバックする
- レスポンスの写真データにも `logTag` を含める
- `fileName` はユーザー入力ではなく、コンテナ番号、タグ名、連番からサーバー側で自動生成する
- 連番は同一コンテナ番号・同一タグ内で既存最大値を確認して次番号を採番する
- 連番採番は backend 側で実行する
- 同時アップロードや複数端末操作でも重複しないように、同一コンテナ番号・同一タグ単位で原子的に採番する
- 原子的なカウンターを使うか、重複検知時に再採番してリトライする
- 採番失敗時は写真保存全体が中途半端に残らないようにする

`PUT /photos/{photoId}` の更新処理で、`logTag` を更新できるようにする。

- 写真名だけの更新 UI は廃止する
- タグだけの更新を許可する
- タグ変更時は必要に応じて `fileName` も再生成する
- `fileName` 再生成時は、変更後タグ内の次番号を採番する
- 権限チェックは既存の写真更新処理に合わせる
- `PUT /photos/{photoId}` でのタグ変更時も、採番は同じ原子性要件を満たす
- タグ変更時は `photo.update` 相当の監査ログを残す

### 既存データ扱い

既存写真に `logTag` がない場合:

- API レスポンスでは `other` として返す
- 画面表示では `その他` とする
- 既存データの一括移行は必須にしない

## 出力要件

PPT/PDF など既存のレポート出力が写真情報を出している場合、タグも出力対象にする。

- レポートには対象コンテナ番号を必ず表示する
- コンテナ番号はページ見出しまたはセクション見出しに表示する
- レポート上は `タグ`、`写真` の順番に表示する
- 写真名は表示しない
- 既存テンプレートのレイアウトを大きく崩さない
- タグ未設定の写真は `その他` として出力する
- タグは画面と同じ色分けを反映する
- お部屋単位の出力や複数コンテナ番号を含む出力を行う場合は、コンテナ番号ごとに写真をまとめる

## 多言語要件

アプリ本体で i18n を維持する場合、タグ表示も翻訳対象にする。

初期対応の日本語表示:

- コンテナ番号
- 搬入
- 搬出
- シール
- 損傷
- その他

英語表示案:

- Container No.
- Inbound
- Outbound
- Seal
- Damage
- Other

中国語、ベトナム語は既存 i18n 方針に合わせて追加する。

## 将来拡張要件

### AIコンテナ番号照合

将来的に、`コンテナ番号` タグの写真を対象に AI/OCR による番号照合を行う。

- 写真内のコンテナ番号を読み取る
- 登録済みのコンテナ番号と照合する
- 一致、不一致、読み取り不可の結果を持つ
- 不一致または読み取り不可の場合は、写真一覧やコンテナ詳細で確認しやすく表示する
- 初期実装では AI 照合は行わず、証跡写真を確実に残すことを優先する
- AI 照合結果を保存する場合は、写真レコードに `containerNumberVerification` のような項目を追加する

## 実装方針

1. 要件を固定する
   - アプリ名、サブタイトル、タグ種別、保存値、LP 非対象を確定する

2. ブランド差し替えを行う
   - アプリ本体の title、ヘッダー、ロゴ、favicon を `Cong` 用へ変更する
   - `frontend/img/cong-logo.png` と `frontend/img/cong-favicon.png` を参照する

3. CSS 変数を追加・置換する
   - `--cong-*` のブランド変数を定義する
   - アプリ本体の主要色を Cong カラーへ寄せる
   - LP 側の色は変更しない

4. フロントのアップロード下書き状態を拡張する
   - 各写真下書きに `logTag` を持たせる
   - 初期値は `container_number` にする

5. 写真登録 UI にタグプルダウンを追加する
   - 写真名入力欄を削除する
   - 各写真行にタグプルダウンを配置する
   - 各写真行で個別に変更できるようにする

6. 写真保存 API へ `logTag` を送る
   - `finalizePhoto` 相当の処理にタグを含める
   - `fileName` はコンテナ番号、タグ名、連番から自動生成する
   - 連番は同一コンテナ番号・同一タグ内で 3 桁ゼロ埋めにする
   - 連番は同時アップロードでも重複しないように backend で原子的に採番する

7. backend で `logTag` を検証・保存する
   - 許可リストでバリデーションする
   - 未指定時は `container_number` にする
   - タグ変更時は変更前後のタグと `fileName` を監査ログに残す

8. 写真一覧と編集 UI にタグ表示・編集を追加する
   - 写真カードにタグバッジを表示する
   - 写真名は表示しない
   - 写真名修正 UI はタグ編集 UI に置き換える

9. 出力処理にタグを反映する
   - レポート見出しに対象コンテナ番号を表示する
   - PPT/PDF はタグ、写真の順番で出す
   - 写真名は出さない

10. 既存データのフォールバックを確認する
    - `logTag` がない写真が `その他` として表示・出力されることを確認する

11. コンテナ番号表示へ置き換える
    - アプリ本体の `フォルダ` 表示を `コンテナ番号` に置き換える
    - 内部 API や DB 名称は必要がなければ維持する

12. フォルダパスワード機能は現状維持する
    - 鍵付きフォルダ仕様、パスワード入力、設定、解除 UI は既存のまま残す

13. タグサマリと検索 UI を追加する
   - `folder-detail-title` の下にタグ別件数を表示する
   - タグフィルターと検索スコープ切替を追加する
   - お部屋単位検索用の backend API を追加する
   - 検索 API はページング、並び順、閲覧権限を考慮する

14. 将来のAI照合に備える
    - `コンテナ番号` タグ写真を明確に分類できる状態にする
    - 初期実装では AI 照合は行わない

## 受け入れ条件

- アプリ本体の名称が `Cong` になっている
- サブタイトルとして `Container Log` が表示される
- アプリ本体のロゴが `cong-logo.png` に差し替わっている
- favicon が `cong-favicon.png` に差し替わっている
- LP は変更されていない
- アプリ本体の主要色が Cong カラーに変わっている
- アプリ本体で `フォルダ` 表示が `コンテナ番号` に変わっている
- フォルダパスワード機能は既存どおり使える
- 写真登録時、写真名入力欄が表示されない
- 写真登録時、タグプルダウンが表示される
- タグプルダウンには `コンテナ番号` `搬入` `搬出` `シール` `損傷` `その他` が表示される
- タグの初期値は `コンテナ番号` になっている
- `コンテナ番号` タグ写真を、入力したコンテナ番号の証跡として登録できる
- 複数写真登録時、写真ごとに別々のタグを選択できる
- 写真名は `コンテナ番号_タグ名_連番` で自動生成される
- 写真名の連番は同一コンテナ番号・同一タグ内で 3 桁ゼロ埋めになっている
- 同時アップロードでも写真名の連番が重複しない
- 写真一覧で写真名が表示されない
- 保存後の写真一覧でタグが確認できる
- タグが色分けされている
- 保存済み写真のタグを編集できる
- タグ編集時に変更前後のタグと `fileName` が監査ログに残る
- `folder-detail-title` の下にタグ別件数サマリが表示される
- タグで写真を絞り込める
- 検索範囲を `このコンテナ` と `このお部屋` で切り替えられる
- `このお部屋` 検索は backend API 経由で実行される
- お部屋単位検索はページングできる
- お部屋単位検索は閲覧権限のない写真を返さない
- API レスポンスに `logTag` が含まれる
- 既存写真はタグ未設定でも `その他` として表示される
- PPT/PDF 出力はタグ、写真の順番で表示される
- PPT/PDF 出力に対象コンテナ番号が表示される
- PPT/PDF 出力に写真名は表示されない
