# クエストモード MVP 要件

更新日: 2026-05-09

## 目的

現在の「写真をアップロードしてコメントする」運用に加えて、先にテキストで「この写真を撮ってきて」と依頼し、あとから写真を添付して完了できるクエストモードを追加する。

既存の写真保存、コメント、PPT/PDF 出力の仕組みをできるだけ流用しつつ、写真が存在しない依頼段階も扱えるようにする。

## MVP 方針

- まずは最小構成で実装する
- クエストはフォルダ配下の新しいリソースとして扱う
- クエストには複数枚の写真を添付できる
- クエストモードでは写真ごとのコメント欄は持たず、クエストコメントだけで運用する
- レポート出力は、完了済みクエストに紐づく写真のみ対象にする
- 未対応・撮影中のクエストは MVP ではレポート出力しない

## 画面構成

フォルダ詳細画面に、以下の 2 モードを切り替えるタブを追加する。

- フォトモード
- クエストモード

### フォトモード

既存の写真アップロード UI と写真一覧を表示する。

- `photo-files`
- アップロード対象一覧
- 写真名
- 初回コメント
- アップロードボタン
- 既存の `photo-card` 一覧

### クエストモード

クエスト作成 UI とクエスト一覧を表示する。

- クエスト本文入力欄
- クエスト作成ボタン
- クエスト並び替えセレクト
- `quest-card` 一覧

## クエスト作成要件

- クエスト本文は必須
- クエスト本文は 100 文字以内を目安にする
- クエストは選択中フォルダに作成する
- 作成直後のステータスは `未対応` とする

クエスト本文の例:

- 玄関ドアの傷を撮ってきて
- 2階廊下の非常灯を撮ってきて
- メーター盤のラベルが読める写真を撮ってきて

## ステータス要件

クエストのステータスは以下の 3 つとする。

- 未対応
- 撮影中
- 完了

### 未対応

- クエスト作成直後の状態
- 写真がまだ 1 枚もない
- レポート出力対象外

### 撮影中

- 写真が 1 枚以上あるが、管理者がまだ完了していない状態
- 再撮影依頼中もこの状態として扱う
- 追加写真をアップロードできる
- レポート出力対象外

### 完了

- 管理者が `完了` ボタンを押した状態
- レポート出力対象
- 完了後もコメント追加可能
- 完了後に写真が追加された場合は、自動で `撮影中` に戻す

## ステータス遷移

基本の遷移は以下とする。

1. クエスト作成
2. `未対応`
3. 写真を 1 枚以上アップロード
4. `撮影中`
5. 管理者が `完了` ボタンを押す
6. `完了`

完了後に写真が追加された場合:

1. `完了`
2. 写真を追加
3. `撮影中`

## 権限要件

- クエスト作成: フォルダにアクセスできる人
- 写真追加: フォルダにアクセスできる人
- コメント追加: フォルダにアクセスできる人
- 完了ボタン: 管理者のみ
- クエスト編集: 作成者または管理者
- クエスト削除: 作成者または管理者

## quest-card 要件

`quest-card` には以下を表示する。

- クエスト番号
- クエスト本文
- ステータス
- 作成者
- 作成日時
- アップロード済み写真一覧
- 写真追加ボタン
- クエストコメント欄
- 完了ボタン

`完了` ボタンは管理者にのみ表示する。

## クエスト写真要件

- 1 クエストに複数枚の写真を添付できる
- 写真保存は既存の写真アップロード処理をできるだけ流用する
- 写真には `questId` を紐づける
- 写真名は既存の `fileName` を使う
- 写真名の最大文字数は既存仕様に合わせて 20 文字以内とする
- クエストモードでは写真ごとのコメント欄は表示しない
- 重複写真検知は既存仕様に合わせてフォルダ単位で行う

## コメント要件

- コメントはクエストに紐づける
- 再撮影依頼もクエストコメントとして保存する
- 完了後もコメント追加できる
- クエストコメントは投稿者、投稿日時を持つ
- クエストコメントは編集・削除できるようにする
- 編集・削除権限は既存コメントと同様に、作成者または管理者とする

## 並び替え要件

クエストカード一覧には表示順切替を用意する。

MVP では手動ドラッグ並び替えは行わず、以下の表示順を選択できるようにする。

- 対応順
- 新しい順
- 古い順

### 対応順

デフォルト表示順とする。

ステータス順は以下。

1. 未対応
2. 撮影中
3. 完了

同じステータス内では新しい順とする。

### 新しい順

作成日時の新しい順で表示する。

### 古い順

作成日時の古い順で表示する。

## レポート出力要件

- 通常フォトモードの写真は今まで通り出力する
- クエスト写真は、クエストが `完了` の場合のみ出力する
- `未対応` と `撮影中` のクエストは出力しない
- 写真 1 枚 = 1 スライドの既存方針を維持する
- クエストに複数写真がある場合、写真枚数分のスライドを作成する
- クエスト写真の各スライドには、クエスト本文を表示する
- クエストコメントは、同じクエストに紐づく各写真スライドに表示する

出力イメージ:

```text
クエスト: 玄関ドアの傷を撮ってきて
写真名: 玄関ドア_アップ

コメント:
1. もう少しアップで撮ってください
2. アップ写真を追加しました
```

## データ設計方針

クエストは写真とは別リソースとして保存する。

推奨方針:

- `quest` を新しいリソースとして追加する
- `photo` は既存リソースを流用する
- `photo` に `questId` を追加してクエストと関連付ける
- クエストコメントは `questId` に紐づける
- 写真コメントはクエストモードでは使用しない

避けたい方針:

- 写真がないクエストを `photo` として保存する

理由:

- 画像なしの `photo` ができると、既存の一覧、PPT/PDF 出力、削除、容量計算、重複判定が複雑になるため

## API 要件案

追加 API の候補は以下。

```text
GET    /folders/{folderId}/quests
POST   /folders/{folderId}/quests
PUT    /quests/{questId}
DELETE /quests/{questId}

GET    /quests/{questId}/comments
POST   /quests/{questId}/comments
PUT    /quests/{questId}/comments/{commentId}
DELETE /quests/{questId}/comments/{commentId}
```

写真アップロードは、既存 API を拡張して `questId` を受ける方針を優先する。

```text
POST /folders/{folderId}/photos/upload-url
POST /folders/{folderId}/photos
```

`POST /folders/{folderId}/photos` に `questId` が指定された場合:

- 写真をクエスト写真として保存する
- 対象クエストが `完了` なら `撮影中` に戻す
- 対象クエストが `未対応` なら `撮影中` にする

## MVP でやらないこと

- 未対応クエストのレポート出力
- 撮影中クエストのレポート出力
- 手動ドラッグによる並び替え
- 写真ごとの採用/不採用フラグ
- 写真ごとの承認
- 写真ごとのコメント欄
- クエストテンプレート
- 担当者アサイン
- 期限管理

## 実装時の注意

- 既存の通常写真とクエスト写真を同じフォルダ出力で扱う
- 完了済みクエストの写真のみレポート対象にする
- 完了後の写真追加で `撮影中` に戻ることを必ず保証する
- クエストコメントだけで運用するため、PPT/PDF 出力ではクエストコメントを写真スライドに展開する
- クエスト写真も容量計算、削除、アーカイブの対象に含める
- 重複写真検知は既存仕様に合わせてフォルダ単位のままとする
